# whiteeagles.sk — аудит и стратегия роста без рекламного бюджета

**Дата:** 3 августа 2026
**Цель:** выйти в топ и получать заявки от русскоязычных предпринимателей в Словакии без платной рекламы.

---

## 0. Главный вывод за 30 секунд

**Сайт не «просел в выдаче». Он структурно невидим для Google.**

За 14 дней настоящий Googlebot (проверено по IP-диапазону `66.249.*`) сделал по всем страницам сайта **порядка 40 запросов**. Из них самая посещаемая роботом страница — `https://whiteeagles.sk/` (35 обращений), которая отдаёт **пустую страницу ошибки Next.js с HTTP 200** и без единого слова контента.

То есть: главная точка входа домена — куда идут прямые заходы, брендовые запросы и все внешние ссылки — для Google выглядит как сломанная пустая страница, которая при этом рапортует «всё в порядке, 200 OK».

Пока это не исправлено, любая работа над контентом и ссылками бессмысленна: Google просто не тратит краулинговый бюджет на домен, который в корне отдаёт мусор.

Хорошая новость: **производительность и разметка у сайта в порядке** (TTFB ~150 мс, gzip, статический экспорт, честный SSR, богатый JSON-LD, hreflang, sitemap). Сломано именно то, что чинится за один день. А ниша русскоязычных услуг в Словакии — почти пустая с точки зрения локальных игроков.

## 2. Критические технические поломки

### 2.1. Корень домена отдаёт страницу ошибки (блокер №1)

```
$ curl -I https://whiteeagles.sk/
HTTP/1.1 200 OK
Content-Length: 4969
```

Тело ответа:

```html
<html id="__next_error__">...404: This page could not be found...
...digest":"NEXT_REDIRECT;replace;/sk;307;"
```

Что происходит: при статическом экспорте `redirect()` из серверного компонента не превращается в HTTP-редирект — он «запекается» в RSC-payload. Nginx отдаёт статический `index.html`, в котором нет ни `<title>`, ни `<meta http-equiv="refresh">`, ни заголовка `Location`. Браузер с JS доедет до `/sk/`. Краулер видит пустую 200-страницу.

**Последствия:** вес всех внешних ссылок и брендовых заходов упирается в тупик; Google снижает частоту обхода всего домена.

**Фикс:** серверный `301` на уровне nginx (см. 2.5). Одна строка.

---

### 2.2. Любая несуществующая страница отдаёт 200 (блокер №2)

```
$ curl -o /dev/null -w "%{http_code}" https://whiteeagles.sk/ru/nonexistent-page-test/
200
```

Причина — в nginx:

```nginx
location / {
    try_files $uri $uri/ /index.html;   # ← фолбэк на сломанный index.html с кодом 200
}
```

Каждый битый URL, каждая ссылка с опечаткой, каждый URL из сканеров-ботов возвращает `200 OK` с той же пустой страницей ошибки. Для Google это **soft 404** — один из сильнейших негативных сигналов качества на уровне всего домена. Индекс засоряется бесконечным числом «страниц» с идентичным пустым содержимым.

В логах видно, как боты долбятся в `/wp-config.php`, `/.env`, `/.git/config`, `/.aws/credentials` — **и всё это получает 200 OK**.

### 2.3. Четыре копии сайта вместо одной

```
http://whiteeagles.sk/       → 200 (нет редиректа на HTTPS)
https://www.whiteeagles.sk/  → 200 (нет редиректа на без-www)
https://www.whiteeagles.sk/ru/ → 200
https://whiteeagles.sk/ru/   → 200
```

В конфиге nginx `server_name whiteeagles.sk www.whiteeagles.sk;` в обоих блоках, `listen 80` без редиректа. Каждая страница существует в 4 вариантах. Canonical-теги частично спасают, но сигналы всё равно размазываются, а HTTP-версия — ещё и минус к доверию.

### 2.4. Разметка отзывов без отзывов — риск ручных санкций

В JSON-LD на каждой странице:

```json
"aggregateRating": {"ratingValue": "4.9", "reviewCount": "24"}
```

Это self-serving review markup на `Organization` и `ProfessionalService`. Google явно запрещает такую разметку для собственной организации без реальных, проверяемых отзывов на странице. В лучшем случае игнорируется, в худшем — ручные меры за спам структурированными данными. **Убрать до появления настоящих отзывов** (а настоящие лучше собирать в Google Business Profile — см. 5.2).

### 2.5. Готовый патч nginx

```nginx
# 1. HTTP → HTTPS, всё на один хост
server {
    listen 80 default_server;
    server_name whiteeagles.sk www.whiteeagles.sk;
    return 301 https://whiteeagles.sk$request_uri;
}

# 2. www → без www
server {
    listen 443 ssl;
    server_name www.whiteeagles.sk;
    ssl_certificate     /etc/letsencrypt/live/whiteeagles.sk/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/whiteeagles.sk/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
    return 301 https://whiteeagles.sk$request_uri;
}

# 3. Основной хост
server {
    listen 443 ssl;
    server_name whiteeagles.sk;
    root /var/www/html;
    index index.html;

    ssl_certificate     /etc/letsencrypt/live/whiteeagles.sk/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/whiteeagles.sk/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

    # КЛЮЧЕВОЕ: корень отдаёт настоящий 301, а не пустую страницу
    location = / {
        return 301 https://whiteeagles.sk/sk/;
    }

    location ~* \.(jpg|jpeg|png|gif|ico|css|js|webp|svg|woff|woff2|ttf|eot)$ {
        expires 1y;
        add_header Cache-Control "public, no-transform";
        access_log off;
    }

    # КЛЮЧЕВОЕ: убран фолбэк на index.html → честный 404
    location / {
        try_files $uri $uri/ $uri.html =404;
    }

    error_page 404 /404.html;
    location = /404.html { internal; }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    }
}
```

Проверка перед применением: `nginx -t && systemctl reload nginx`.

> **Нюанс автоопределения языка.** Сейчас `/` пытается угадать язык браузера на клиенте. С серверным 301 на `/sk/` это уходит. Правильный компромисс: `301 → /sk/` (словацкий как основной рынок и `x-default`), а переключатель языков в шапке остаётся. Если хочется сохранить автоопределение — делать его через nginx `map $http_accept_language` с кодом 302, но для SEO стабильный 301 надёжнее.

### 2.7. Аналитика, скорее всего, не считает конверсии

В коде события уходят **только в `dataLayer`**:

```ts
// src/utils/analytics.ts
window.dataLayer.push({ event: eventName, ...params });
```

При этом GA4 подключён **напрямую через gtag.js** (`G-31E4MKB8QX`), параллельно с GTM (`GTM-KK389G5B`). `dataLayer.push` сам по себе в GA4 не попадает — нужны настроенные теги в GTM.

**Что проверить в GTM:**
1. Есть ли триггеры Custom Event на `form_submit`, `order_send`, `contact_click`, `cta_click` и теги GA4 Event, отправляющие их в `G-31E4MKB8QX`. Если нет — **ни одна заявка в GA4 не видна**, и «нулевая конверсия» может быть артефактом замера.
2. Нет ли в GTM ещё одного GA4 Configuration тега на тот же `G-31E4MKB8QX` — тогда просмотры считаются дважды (сайт грузит gtag.js и GTM одновременно).
3. Отметить `order_send` как **ключевое событие (key event)** в GA4 — иначе не будет конверсий в отчётах.

## 3. Контент: почему он не может ранжироваться

Сейчас: **6 статей, переведённых на 3 языка = 18 URL**. Размер русских статей — 2.6–5 КБ markdown, это ~400–800 слов. Последняя публикация — **13 мая 2026**, сайт не обновлялся с 4 июня.

Проблема глубже объёма — в выборе тем. Русские статьи это дословные переводы словацких:

- «Сколько стоит создание сайта в 2026 году?»
- «WordPress или самописный сайт»
- «Как настроить Google Analytics 4»
- «SEO аудит: как проверить свой сайт самостоятельно»

Это **общероссийские инфо-запросы без географической привязки**. По ним конкуренция — весь рунет: Хабр, VC.ru, Тинькофф Журнал, сотни агентств с DR 60+. Сайт с DR ~0 и 40 страницами не займёт по ним ничего. И даже если займёт — трафик придёт из России и Казахстана и никогда не станет заявкой в Словакии.

**Ключевая мысль:** нужно уйти от темы «сайты» к теме «бизнес в Словакии на русском». Русскоязычный предприниматель в Словакии не гуглит «сколько стоит сайт». Он гуглит «как открыть s.r.o. в Словакии», «что такое eKasa», «нужен ли мне DPH», «как принимать оплату картой». Сайт нужен ему **после** — и купит он у того, чью статью прочитал.

## 4. Рынок: сколько там вообще людей и кто конкурент

**Аудитория.** Русскоязычных в Словакии — русские, украинцы (включая ~100+ тыс. с временной защитой), белорусы, казахстанцы. Совокупно это шестизначное число людей, но **предпринимателей среди них** — на порядки меньше, и **ищущих подрядчика на сайт прямо сейчас** — единицы запросов в месяц.

Отсюда честный вывод: **чистое SEO по запросам «создание сайта Братислава» не наполнит воронку.** Речь про десятки показов в месяц, не тысячи. Ставить на это как на единственный канал — ошибка.

**Но.** Посмотрим, кто занимает эту выдачу сейчас:

- `medialine.by`, `slam.by`, `qmedia.by` — Минск
- `web-agent.by` — Беларусь
- `site2u.com.ua` — Украина
- `sitecreative-eu.com`, `cyborg-studio.com` — офшорные студии

**Ни одного словацкого s.r.o.** Все — удалённые подрядчики из другой юрисдикции.

Это и есть позиционный разрыв. Кирилл может заявить то, чего не может ни один из них:

- Словацкое s.r.o. → **фактура с IČO/DIČ**, которую можно провести в расходы
- **10 лет в Словакии** → знание eKasa, DPH, GDPR по словацкому праву
- Физическое присутствие в Братиславе → **личная встреча**
- Русский + словацкий → **общение с клиентом на русском, а с его словацкими партнёрами и госорганами — на словацком**

Ни `.by`, ни `.ua` студия не выставит словацкую фактуру и не придёт на встречу. Это не «преимущество для лендинга» — это то, вокруг чего строится вся семантика и все тексты.

**Отдельно:** брендовый запрос «White Eagles Bratislava» намертво занят флорбольным клубом FBC White Eagles Bratislava (Instagram, Facebook, FinStat, SZFB). Брендовое SEO по этому имени бесперспективно — продвигать нужно **личный бренд «Кирилл Мосин»** и домен `whiteeagles.sk`, а не словосочетание.

### 5.2. Канал 2 — Google Business Profile (неделя 1–2) ⭐ самый недооценённый

**Это самый мощный бесплатный источник локальных заявок, и его, судя по всему, нет.**

Что даёт GBP:
- попадание в локальный пак (карта + 3 карточки над органикой) по запросам `tvorba web stránok Bratislava`, `webdesign Bratislava` — там, где обычным SEO пробиться нужны годы
- **отзывы**, которые можно легально разметить и показывать (в отличие от текущей фейковой разметки)
- отдельный канал звонков и сообщений, полностью бесплатный
- сущность-подтверждение для Google: адрес в GBP + тот же адрес в JSON-LD + тот же в Firmy.sk = Google понимает, что бизнес реален

Что делать:
1. Создать/подтвердить профиль на **Holíčska 7, Bratislava** (тот же адрес, что в `ProfessionalService`).
2. Категории: `Web designer` (основная), `Marketing agency`, `Software company`.
3. Описание **на словацком**, но с явным упоминанием обслуживания на русском.
4. Атрибуты и услуги: перечислить все 6 услуг с сайта, каждая со ссылкой на свою страницу `/sk/service/*`.
5. **Собрать 8–12 отзывов у существующих клиентов из портфолио** (Biliardovna, Bodabo, Studio Krásy, Top Sklad, Ram Service, Rebuy Stars, Severske Drevo, Slov Uni Sport, Chicago, Moj Servis, Top Kobka, Synchro Žralok). У тебя уже есть 12+ реальных клиентов — это готовый пул. Просить по одному в неделю, не пачкой.
6. Постить в GBP раз в неделю (посты индексируются и держат профиль «живым»).

### 5.3. Канал 3 — Контент под русскоязычного предпринимателя в Словакии (месяцы 1–4)

Переориентация с «услуг» на «проблемы релоканта, открывающего бизнес».

**Правила исполнения:**

- **Одна статья в неделю, минимум 1500–2000 слов.** Текущие 400–800 слов не конкурентоспособны.
- Каждая статья — **сначала на русском** (там пусто), потом на словацком (там объём, но и конкуренция). Английский — по остаточному принципу или вообще отключить: он не приносит ни трафика, ни заявок, зато размывает краулинговый бюджет втрое.
- В каждой статье — **личный опыт**: «когда я регистрировал s.r.o. в 2016», «мой клиент из Stupavy столкнулся с». Это E-E-A-T, который офшорные студии подделать не могут.
- В конце каждой статьи — CTA на бесплатный аудит, но **мягкий и релевантный теме**, а не общий баннер.
- **Перелинковка**: каждая новая статья ссылается на 2–3 старые и на релевантную страницу услуги.

Это может удвоить доменный вес.

**4.2. Бесплатные словацкие каталоги** (NAP строго идентичен GBP):

## 7. Чего ожидать (честно)

| Срок | Результат |
|---|---|
| 2–4 недели после фикса технички | Рост обхода Googlebot в 5–10 раз, страницы начинают появляться в GSC |

**Важно про ожидания:** русскоязычный сегмент в Словакии — маленький. Он даст **качественные, конверсионные, но немногочисленные** заявки. Основной объём трафика в перспективе всё равно придёт со словацких запросов. Правильная модель: **русский контент = дифференциация и конверсия, словацкий контент = объём.** Не отказываться от `/sk/` в пользу `/ru/` — делать оба, но русский первым, потому что там можно выиграть быстро.
